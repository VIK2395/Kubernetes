# EKS IAM Authentication and RBAC

## 🔐 The Big Picture: AuthN + AuthZ in EKS

```txt
kubectl command
      │
      ▼
┌────────────────────────────────────────────-─────────┐
│              EKS Control Plane                       │
│                                                      │
│  1. AUTHENTICATION (Who are you?)                    │
│     └── AWS IAM Authenticator  ◄── aws-auth ConfigMap│
│                                                      │
│  2. AUTHORIZATION (What can you do?)                 │
│     └── Kubernetes RBAC                              │
│          └── Roles / ClusterRoles                    │
│          └── RoleBindings / ClusterRoleBindings      │
└─────────────────────────────────────────────────────-┘
```

## 🔗 How They Relate — Step by Step

### Step 1: Authentication via IAM (AWS Layer)

When you run kubectl, your request carries an IAM identity token (generated by aws eks get-token). The AWS IAM Authenticator on the EKS control plane validates this token against AWS IAM.

- The aws-auth ConfigMap is the bridge here — it maps IAM entities (users/roles) → Kubernetes usernames/groups.

Example from aws-auth:
```txt
mapRoles:
  - rolearn: arn:aws:iam::123456789:role/MyDevRole
    username: dev-user
    groups:
      - dev-group
```

This says: "If you authenticate as MyDevRole in IAM, you are known as dev-user in Kubernetes, belonging to dev-group."

### Step 2: Authorization via Kubernetes RBAC (K8s Layer)

Once authenticated, Kubernetes doesn't know or care about IAM anymore. It uses the username/group from Step 1 and checks native Kubernetes RBAC objects (as described in the GitHub doc):

<img width="625" height="119" alt="image" src="https://github.com/user-attachments/assets/1bfe82ab-5ce6-498b-992a-b1613677687f" />

Example:
```txt
# ClusterRoleBinding
subjects:
  - kind: Group
    name: dev-group        # ← matches the group from aws-auth
roleRef:
  kind: ClusterRole
  name: view
```
This says: "The dev-group group can perform view actions on the cluster."

### 🧩 The Full Connection

```txt
IAM Role (MyDevRole)
        │
        │  aws-auth ConfigMap maps it to:
        ▼
Kubernetes username: "dev-user"
Kubernetes group:    "dev-group"
        │
        │  RBAC RoleBinding/ClusterRoleBinding grants:
        ▼
Permissions to interact with K8s API
(e.g., get pods, list deployments, etc.)
```
